总览
What / Why

总览

一个常驻 Windows 桌面的轻量工具：把文件随手"扔"进悬浮球暂存，需要时再拖出来；同时记录复制过的文本、图片和文件，供随时取回。

要解决的问题

在一台电脑上搬运内容时，常见三类摩擦：

  1. 文件占位难：把一个文件从深层目录拖到另一个位置（或拖进微信、邮件），中途要找窗口、来回切换、路径深记不住，一次拖不完还得再来一遍。
  2. 剪贴板只有一份：系统剪贴板只保留最后一次复制，之前复制的文本、截图、文件路径全部丢失，想找回只能重新去原处复制。
  3. 取出路径不确定：临时放一下的东西，回头既不记得放哪了，也不确定原文件是不是还在。

产品目标

  • 提供一处"随手进、随手出"的暂存空间——拖进来即存，拖出去即用，全程不超过两次拖拽。
  • 把剪贴板从"仅最后一条"变成可回溯、可搜索的历史。
  • 对暂存的文件明确给出是否仍然可用的反馈，避免取用时才发现失效。

目标用户与使用场景

单个 Windows 用户，在自己的电脑上做文档整理、素材搬运、跨窗口递送。典型场景：写报告时先把待引用的图片、表格拖到悬浮球备着；整理资料时把散布各处的文件先"聚"到中转站再统一拖去归档目录；复制了一堆链接和段落，事后从历史里逐条找回。

核心任务与完成条件

核心任务把内容"暂存"到一个随手可及的位置，之后再取出使用。
触发起点用户把文件拖到悬浮球上；或用户执行了一次系统复制。
完成条件文件被成功复制/移动到目标位置；或某条历史内容被重新写入系统剪贴板。
失败与恢复原文件已移动/删除时，条目标记失效并提供"重新定位"与"移除"。

共享业务对象：条目（Item）

中转站与剪贴板历史共用同一个"条目"抽象：两者都是"一条可被再次取用的内容记录"，差别只在来源与取用方式。中转站条目的取用方式是拖出，剪贴板条目的取用方式是复制回剪贴板。

维度中转站条目剪贴板条目
来源用户拖拽文件入球系统复制事件
内容载体原文件路径引用文本内容 / 图片数据 / 文件路径
取用方式拖出到目标（复制或移动）一键写回系统剪贴板
失效可能原文件被移动或删除文本图片不会失效；文件型条目会同中转站一样失效

本期范围（P0）

P0 · 悬浮球常驻与拖入暂存 P0 · 入口菜单 P0 · 中转站列表与拖出 P0 · 失效识别与恢复 P0 · 剪贴板监听与历史 P0 · 复制回剪贴板 P0 · 置顶与清理 P0 · 设置（上限、开关、快捷键、拖出行为）

明确不做

局域网 / 跨设备传输 云同步与账号 对暂存文件做内容编辑 团队共享与权限体系

本次"本机快传"限定为同一台电脑内的投递，本质由"中转站拖出"与"复制回剪贴板"两个动作承担，不引入任何网络模块。

核心流程与设计
Happy path

核心旅程：把文件暂存再取出

1
拖入从资源管理器把 1 个或多个文件拖到桌面悬浮球上，悬浮球放大并提示"松手即暂存"。
2
暂存松手后条目进入中转站，悬浮球右上角计数更新，出现"已暂存 N 个文件"提示。
3
打开点击悬浮球展开入口菜单，选择"文件中转站"。
4
取出把条目从面板拖到目标窗口（微信、邮件、资源管理器、其他应用）。默认复制一份到目标位置。
5
完成目标位置出现文件；条目仍留在中转站，可再次拖出。确认不再需要时移除或清空。

恢复路径：原文件失效

!
发现打开中转站时，原文件已被移动/删除的条目显示为失效态，并给出原因。
↺
处理用户可选择"重新定位"到文件的新位置，或直接"移除"该条目。失效条目不可拖出。

核心旅程：取回剪贴板历史

1
记录用户复制文本 / 图片 / 文件，历史中自动新增条目，重复内容不重复记录。
2
查找展开"剪贴板历史"，用类型筛选或关键词搜索定位目标条目。
3
取回点击（或按回车）条目，内容写回系统剪贴板，提示"已复制到剪贴板"，可直接粘贴。
Decisions

关键产品决策

决策内容理由
悬浮球优先于窗口常驻一个小球作为唯一入口，点击才展开面板目标用户要的是"随手可用"，常驻大窗口会干扰桌面工作；小球同时天然成为拖拽落点
拖入即存，无需确认文件拖到球上松手立刻暂存，不弹确认框暂存是低风险、可撤销的动作，移除即可回退；加确认会打断连续搬运
中转站只记路径不复制文件实体，只记录原路径引用避免占用额外磁盘空间，也避免大文件复制耗时
拖出默认复制拖出不改变原文件，右键才提供"移动至此"复制可逆、不会误伤原文件；移动是破坏性动作，需用户显式选择
失效条目显式标注原文件不可用时条目变灰并禁止拖出只存引用必须承担失效风险，因此要把风险在界面上说清楚，而不是拖出去才发现
历史自动限量默认保留最近 500 条，置顶不过期剪贴板历史会无限增长，需要自动收敛；置顶给用户保留重要内容的确定性

功能需求

F1 · 桌面悬浮球 feature-floating-ball

产品的唯一常驻入口：既是拖拽落点，也是打开面板的按钮。

行为：应用启动后，悬浮球显示在主屏幕右下角，始终位于其他窗口之上。球上以角标显示当前中转站的条目数；条目数为 0 时隐藏角标。球体可被拖动到屏幕其他位置，位置在下次启动时保留。

触发响应
单击球体展开入口菜单
再次单击 / 点击面板外空白收起菜单或面板
拖拽文件进入球体范围球体放大并进入"拖入悬停态"（见 F2）
拖动球体本身移动球体位置，松手后保存新位置

边界：当用户正在拖动球体本身时，不响应文件拖入，避免手势冲突。

F2 · 拖入暂存 feature-drop-to-shelf

把文件从资源管理器或任意应用拖到悬浮球上，松手即完成暂存。

交互流程：文件进入球体范围 → 球体放大、显示虚线落点环与提示"松开鼠标，把文件暂存到中转站" → 松手 → 文件写入中转站 → 提示"已暂存 N 个文件"，角标同步更新。

处理规则

  • 支持一次拖入多个文件，全部按各自条目入站。
  • 拖入的是文件夹时，记录该文件夹路径为一条条目（不对其内部文件展开）。
  • 同一路径重复拖入时视为同一条目，仅更新其暂存时间并移到列表顶部，不产生重复项。
  • 暂存不复制文件实体，只记录路径引用。

边界与失败

情况处理
松手时鼠标已移出球体范围取消本次拖入，不产生条目
文件无读取权限该条目标记为不可用并提示"无法读取"，其余文件正常入站
拖入过程中应用退出未松手的文件不入站，无残留

F3 · 入口菜单 feature-entry-menu

点击悬浮球后展开的二级导航，负责把用户送进三个面板之一。

菜单包含三项：文件中转站（附当前条目数）、剪贴板历史、设置。选择后菜单收起，对应面板在球附近展开。面板内提供返回箭头回到菜单。全局快捷键再次按下可收起当前面板。

状态：同一时刻只允许打开一个面板；打开新面板时自动关闭旧面板。菜单与面板均不夺取前台焦点，用户仍能操作原窗口（面板打开时允许拖出到其他窗口）。

F4 · 中转站列表 feature-shelf-list

浏览与管理已暂存的文件条目。

列表规则：置顶条目始终在最前，其余按暂存时间从新到旧排列。每行显示图标、文件名、大小与来源路径。顶栏显示条目总数。

行内操作

操作结果
置顶条目固定到列表顶部并高亮；再次点击取消置顶
打开所在位置在资源管理器中定位并选中原文件；文件失效时此项禁用
移除条目移出中转站，不删除原文件
清空见"规则与状态"中的二次确认要求

搜索：按文件名或路径实时过滤（P1）。空态：显示"中转站是空的，把文件拖到悬浮球上即可暂存"。

F5 · 从中转站取出 feature-shelf-dragout

把暂存的文件投递到目标位置，是本产品的核心取用动作。

交互流程：按住条目向左/向目标窗口拖动 → 光标携带文件预览 → 在目标位置（资源管理器文件夹、聊天窗口、邮件客户端等）松手 → 文件写入目标位置 → 提示结果。条目仍保留在中转站。

规则

  • 默认复制：拖出产生一份副本，原文件不受影响。
  • 移动：右键条目选择"移动至此"后才执行剪切，原位置文件消失，条目从中转站移除。
  • 目标位置已存在同名文件时，交由系统重名策略处理（默认重命名保留两份），本产品不额外弹窗。
  • 失效条目不可拖出，拖动时无响应。
说明：拖出到聊天/邮件类应用依赖系统剪贴板文件格式，部分应用仅接受单文件，多选拖出时按应用能力投递。

F6 · 原文件失效处理 feature-invalid-file

因为中转站只记录路径引用，必须让失效风险在界面上可见、可处理。

识别时机：打开中转站面板时、拖出前、以及应用获得焦点时，校验各条目原路径是否仍然存在。校验不通过的条目标记为失效。

失效态呈现：条目变灰，标注"原文件已移动或删除"，并给出两个动作——重新定位（让用户手动选择文件的新位置，选中后条目恢复可用并更新路径）与移除。

边界：失效条目禁止拖出与"打开所在位置"。若用户重新定位后再次失效，重复上述流程。

F7 · 剪贴板捕获 feature-clipboard-capture

自动记录用户复制过的内容，形成可回溯的历史。

捕获范围：文本、图片、文件列表三类。应用在后台持续监听系统剪贴板变化，变化时生成新条目。

类型内容处理
文本保存完整文本；列表标题取前若干字符
图片将图片数据保存到应用数据目录，历史中引用该图片
文件记录文件路径列表，呈现方式与中转站条目一致，同样受失效校验约束

规则：与历史中最新一条完全相同的内容不重复记录，仅将该条时间刷新并置顶。仅记录内容本身，不记录来源应用窗口标题。

[TBD] 敏感内容：是否过滤密码管理器等标记为敏感的剪贴板内容，待评审确认，默认按"全部记录"实现。

F8 · 剪贴板历史浏览与检索 feature-clipboard-history

在大量历史条目中快速找到想要的那一条。

浏览：条目按时间从新到旧排列，置顶条目在最前。每条以类型标签（文本/图片/文件）区分，文本显示内容摘要，图片显示缩略图，文件显示文件名与路径。

筛选与搜索（P1）：提供"全部 / 文本 / 图片 / 文件"类型筛选；关键词输入框对文本内容与文件名做实时匹配。筛选项与搜索词可叠加，互不冲突。无匹配结果时显示"没有匹配的记录"。

操作：置顶、删除、清空。置顶条目不参与容量淘汰。

F9 · 复制回剪贴板 feature-clipboard-copyback

把历史条目重新变成"可以直接粘贴"的内容。

流程：点击条目 → 该条内容写入系统剪贴板 → 面板可保持打开或收起 → 提示"已复制到剪贴板" → 用户在原应用中粘贴即得到内容。

规则：写回后的内容即为系统当前剪贴板内容，不额外产生新的历史条目（因为内容与已有条目相同）。图片条目写回的是图片本身，文件条目写回文件引用。文件型条目在失效时提示"原文件已不存在"，不写回。

F10 · 置顶与清理 feature-pin-and-clean

让重要内容稳定留存，让无用内容快速消失。

  • 置顶：中转站与剪贴板均支持。置顶条目固定在顶部，且不参与自动淘汰。
  • 删除单条：直接从列表移除。剪贴板中的图片条目删除时，一并清除其落盘的图片文件。
  • 清空：清空中转站不会删除任何原文件；清空剪贴板历史会删除全部条目及其落盘图片。两者均需二次确认（见"规则与状态"）。

F11 · 设置 feature-settings

让用户控制容量、开关与默认行为。

设置项类型默认值效果
剪贴板历史上限数值（步进调整）500 条超出后自动淘汰最旧的非置顶条目
开机自动启动开关开登录后常驻运行
监听剪贴板开关开关闭后不再产生新历史条目
全局快捷键快捷键录入Ctrl+Shift+V展开/收起入口菜单

规则与状态

全局规则

容量与淘汰

  • 剪贴板历史默认上限 500 条，可在设置中调整。
  • 超出上限时，自动淘汰最旧的非置顶条目；置顶条目不参与淘汰，也不计入上限。
  • 淘汰只影响历史记录；剪贴板中的图片条目被淘汰时，其落盘图片一并清除。
  • 中转站不使用自动淘汰，条目一直保留直到用户移除或清空。

去重

  • 剪贴板：与最新一条内容完全相同时不新增，仅刷新时间。
  • 中转站：同一原路径重复拖入不新增，仅刷新暂存时间并置顶。

可用性（失效）校验

文件型条目（含剪贴板中的文件条目）在以下时机校验原路径是否仍存在：打开对应面板时、拖出前、应用获得焦点时。校验失败即进入失效态，失效条目禁止拖出与定位。

裁剪与显示

  • 文本条目过长时，列表仅显示摘要，完整内容在复制回剪贴板时原样写回。
  • 超长路径在列表中截断显示，悬停可查看完整路径。

隐私与安全

  • 全部数据仅保存在本机，不联网上传。
  • 剪贴板中的图片会落盘到应用数据目录；清空历史或删除条目时同步清除对应文件。

状态含义进入条件离开条件界面表现
可用内容可正常取用入站成功 / 重新定位成功原文件失效，或被移除正常样式，可置顶、可取用

已移除条目不再存在用户移除 / 清空 / 被淘汰—从列表消失
